# キーボードタイプ管理機能の設計

**作成日**: 2026-01-10
**ステータス**: 設計段階（未実装）
**優先度**: 中（Day 30以降に実装予定）

---

## 📋 概要

管理者がキーボードタイプを追加・管理できる機能。ユーザーはキーマップ編集ページで自分のキーボードタイプを選択でき、選択したキーボードタイプに応じてキーボードUIやキー数が動的に変化する。

## 🎯 目的

- **柔軟性**: 現在ハードコードされている「4×6 - 分割型・オーソリニア」を動的に管理
- **拡張性**: 将来的に様々なキーボードレイアウトに対応（5×6、Corne、Lily58、Moonlander等）
- **ユーザビリティ**: ユーザーが自分のキーボードに合ったレイアウトを選択可能

## 🏗 設計方針

### 基本原則

1. **管理者のみが追加可能**: カテゴリー管理と同様の権限モデル
2. **多言語対応**: 最初から `name_ja`, `name_en` カラムを持つ
3. **JSONB で柔軟なレイアウト定義**: キーの座標・配置を柔軟に定義
4. **既存データの移行**: 現在の `keyboard_type` (string) から新しい外部キー方式へ

## 📊 データモデル設計

### 新規モデル: `KeyboardType`

```ruby
# app/models/keyboard_type.rb
class KeyboardType < ApplicationRecord
  # テーブル: keyboard_types
  # カラム:
  # - id: bigint (primary key)
  # - slug: string (一意識別子、例: "split_4x6", "corne_lp")
  # - name_ja: string (日本語名、例: "4×6 - 分割型・オーソリニア")
  # - name_en: string (英語名、例: "4×6 - Split Ortholinear")
  # - layout_data: jsonb (キーの位置・座標情報、後述)
  # - description_ja: text (説明文、任意)
  # - description_en: text (説明文、任意)
  # - created_at: datetime
  # - updated_at: datetime

  has_many :keymap_sets, dependent: :restrict_with_error

  validates :slug, presence: true, uniqueness: true, format: { with: /\A[a-z0-9_]+\z/ }
  validates :name_ja, presence: true, length: { maximum: 100 }
  validates :name_en, presence: true, length: { maximum: 100 }
  validates :layout_data, presence: true

  # i18n対応
  def translated_name
    I18n.locale == :ja ? name_ja : name_en
  end

  def translated_description
    I18n.locale == :ja ? description_ja : description_en
  end
end
```

### `layout_data` (JSONB) の構造

```json
{
  "rows": 4,
  "cols": 6,
  "split": true,
  "hands": {
    "left": [
      {"row": 0, "col": 0, "position": "L0-R0"},
      {"row": 0, "col": 1, "position": "L0-R1"},
      // ... 全24キー分
    ],
    "right": [
      {"row": 0, "col": 0, "position": "R0-R0"},
      {"row": 0, "col": 1, "position": "R0-R1"},
      // ... 全24キー分
    ]
  }
}
```

**フィールド説明:**
- `rows`: 行数
- `cols`: 列数
- `split`: 分割型かどうか（true/false）
- `hands`: 左手・右手のキー配置
  - `row`, `col`: グリッド座標
  - `position`: キーのユニークな識別子（Keymapモデルの `key_position` と対応）

### Phase 3: データ移行

```ruby
# db/migrate/YYYYMMDDHHMMSS_migrate_keyboard_type_data.rb
class MigrateKeyboardTypeData < ActiveRecord::Migration[8.1]
  def up
    # デフォルトの KeyboardType を作成
    default_type = KeyboardType.create!(
      slug: "split_4x6",
      name_ja: "4×6 - 分割型・オーソリニア",
      name_en: "4×6 - Split Ortholinear",
      layout_data: generate_split_4x6_layout
    )

    # 既存の KeymapSet を新しい KeyboardType に紐付け
    KeymapSet.where(keyboard_type_id: nil).update_all(keyboard_type_id: default_type.id)

    # NOT NULL制約を追加
    change_column_null :keymap_sets, :keyboard_type_id, false
  end

  def down
    change_column_null :keymap_sets, :keyboard_type_id, true
  end

  private

  def generate_split_4x6_layout
    # 4×6分割型のレイアウトデータを生成
    {
      rows: 4,
      cols: 6,
      split: true,
      hands: {
        left: (0..3).flat_map { |row| (0..5).map { |col| { row: row, col: col, position: "L#{row}-R#{col}" } } },
        right: (0..3).flat_map { |row| (0..5).map { |col| { row: row, col: col, position: "R#{row}-R#{col}" } } }
      }
    }
  end
end
```

### Phase 4: 古い `keyboard_type` カラム削除

```ruby
# db/migrate/YYYYMMDDHHMMSS_remove_keyboard_type_from_keymap_sets.rb
class RemoveKeyboardTypeFromKeymapSets < ActiveRecord::Migration[8.1]
  def change
    remove_column :keymap_sets, :keyboard_type, :string
  end
end
```

### ユーザー側キーマップ編集ページ

**変更点:**
- キーボードタイプ選択ドロップダウン:
  ```slim
  select data-action="change->keymap-editor#changeKeyboardType"
    - KeyboardType.all.each do |type|
      option value=type.id selected=(type.id == @keymap_set.keyboard_type_id)
        = type.translated_name
  ```
- 選択したキーボードタイプの `layout_data` に基づいてキーボードUIを動的生成（Stimulus）

## ⚠️ 注意事項

### データ移行時の注意

- 本番環境で既存の `KeymapSet` レコードが大量にある場合、Phase 3のデータ移行が時間がかかる可能性
- ダウンタイムを避けるため、バックグラウンドジョブで段階的に移行するか、メンテナンスウィンドウを設ける

### 削除制約

- `KeyboardType` が1つでも `KeymapSet` に使用されている場合、削除不可（`dependent: :restrict_with_error`）
- 削除する場合は、まず該当する `KeymapSet` を別のキーボードタイプに変更する必要がある
