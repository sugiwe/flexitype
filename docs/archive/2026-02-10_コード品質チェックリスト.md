## 1. 国際化（i18n）対応

### 1.1 ハードコードされた文字列の排除

**チェック項目:**
- [ ] ビューに日本語/英語が直接書かれていないか
- [ ] コントローラーのフラッシュメッセージがハードコードされていないか
- [ ] モデルのバリデーションエラーメッセージがハードコードされていないか
- [ ] JavaScriptのアラート/確認メッセージがハードコードされていないか

**良い例:**
```ruby
# Controller
redirect_to root_path, alert: t("flash.user_not_found")

# Model (シンボル形式)
errors.add(:username, :reserved)

# View
= t('navigation.home')
```

**悪い例:**
```ruby
# Controller
redirect_to root_path, alert: "ユーザーが見つかりませんでした"

# Model
errors.add(:username, "は予約されているため使用できません")

# View
ホーム
```

### 1.2 日付フォーマットのi18n化

**チェック項目:**
- [ ] `strftime`を使っていないか
- [ ] 日付フォーマット文字列に日本語が含まれていないか

**良い例:**
```ruby
I18n.l(date, format: :long)
I18n.l(datetime, format: :short)
```

**悪い例:**
```ruby
date.strftime("%Y年%m月%d日")
datetime.strftime("%Y-%m-%d %H:%M")
```

**必要な設定:**
```yaml
# config/locales/ja.yml
ja:
  date:
    formats:
      long: "%Y年%m月%d日"
  time:
    formats:
      long: "%Y年%m月%d日 %H時%M分"
```

## 2. DRY原則（Don't Repeat Yourself）

### 2.1 重複したロジックの抽出

**チェック項目:**
- [ ] 同じコードが3回以上出現していないか
- [ ] 似たようなメソッドが複数のクラスにないか
- [ ] 条件分岐の各ブランチで重複処理がないか

**リファクタリング手法:**
- メソッド抽出（Extract Method）
- クラスメソッド/モジュールへの移動
- `private_class_method`の活用
- Concernsの活用

**例: 重複したグレード判定ロジック**
```ruby
# Before (重複)
def calculate_grade_from_stats(accuracy, wpm)
  if accuracy >= 98 && wpm >= 80
    "legendary"
  # ...
  end
end

def calculate_grade
  if accuracy >= 98 && wpm >= 80
    "legendary"
  # ...
  end
end

# After (DRY)
def self.calculate_grade_from_stats(accuracy, wpm)
  determine_grade(accuracy, wpm)
end

def calculate_grade
  self.grade = self.class.determine_grade(accuracy, wpm)
end

def self.determine_grade(accuracy, wpm)
  # 共通ロジック
end
private_class_method :determine_grade
```

### 2.2 ビューの繰り返しコードのループ化

**チェック項目:**
- [ ] ほぼ同じHTMLブロックが繰り返されていないか
- [ ] `button_to`や`link_to`が連続していないか

**良い例:**
```slim
- %i[yesterday this_week last_week].each do |period|
  = button_to my_period_shares_path(period: period), method: :post do
    = t("history.share.periods.#{period}")
```

**悪い例:**
```slim
= button_to my_period_shares_path(period: 'yesterday'), method: :post do
  = t('history.share.periods.yesterday')
= button_to my_period_shares_path(period: 'this_week'), method: :post do
  = t('history.share.periods.this_week')
/ ... 繰り返し
```

### 2.3 ビューのパーシャル化

**チェック項目:**
- [ ] 100行を超える長いビューファイルがないか
- [ ] 複雑な`if/else`ブロックがないか
- [ ] 同じHTML構造が複数ファイルに出現していないか

**目安:**
- 50行以上のif/elseブロック → パーシャル化を検討
- 100行以上のビューファイル → セクション分割を検討

## 3. パフォーマンス最適化

### 3.1 N+1クエリ問題

**チェック項目:**
- [ ] `each`ループ内で関連レコードにアクセスしていないか
- [ ] `includes`や`preload`、`eager_load`が適切に使われているか

**検出方法:**
```ruby
# 開発環境で確認
# config/environments/development.rb
config.after_initialize do
  Bullet.enable = true
  Bullet.bullet_logger = true
end
```

**良い例:**
```ruby
@users = User.includes(:lesson_records).order(id: :desc)
@lesson_records = @user.lesson_records.includes(:lesson, :user)
```

**悪い例:**
```ruby
@users = User.order(id: :desc)
# ビューで @users.each { |user| user.lesson_records.count } → N+1発生
```

### 3.2 複数回のDBクエリを1回にまとめる

**チェック項目:**
- [ ] 同じテーブルに対して複数回`count`、`average`、`sum`を実行していないか
- [ ] 集計結果を複数回取得していないか

**良い例:**
```ruby
stats = records.select(
  "COUNT(*) AS count",
  "AVG(accuracy) AS avg_accuracy",
  "AVG(wpm) AS avg_wpm"
).first

{
  count: stats.count,
  avg_accuracy: stats.avg_accuracy&.round(2),
  avg_wpm: stats.avg_wpm&.round
}
```

**悪い例:**
```ruby
{
  count: records.count,
  avg_accuracy: records.average(:accuracy)&.round(2),
  avg_wpm: records.average(:wpm)&.round
}
# 3回のクエリが発生
```

### 3.3 定数キャッシュ化

**チェック項目:**
- [ ] メソッド呼び出しのたびに不変リストを生成していないか
- [ ] 環境変数のパース処理が複数回実行されていないか
- [ ] `ActiveSupport::TimeZone.all`などの重い処理が繰り返されていないか

**良い例:**
```ruby
class User < ApplicationRecord
  TIME_ZONE_NAMES = ActiveSupport::TimeZone.all.map(&:name).freeze

  validates :time_zone, inclusion: { in: TIME_ZONE_NAMES }
end
```

**悪い例:**
```ruby
validates :time_zone, inclusion: { in: ActiveSupport::TimeZone.all.map(&:name) }
# バリデーションのたびに生成
```

## 4. コードの一貫性

### 4.1 日付計算の統一

**チェック項目:**
- [ ] `1.day.ago`と`now - 1.day`が混在していないか
- [ ] タイムゾーン処理が一貫しているか

**良い例:**
```ruby
now = Time.current.in_time_zone(timezone)
yesterday = now - 1.day
last_week = now - 1.week
```

**悪い例:**
```ruby
yesterday = 1.day.ago.in_time_zone(timezone)
last_week = now - 1.week
# 一貫性がない
```

### 4.2 適切な継承関係

**チェック項目:**
- [ ] 名前空間内のコントローラーが適切な親クラスを継承しているか
- [ ] 重複した`before_action`がないか

**良い例:**
```ruby
class My::PeriodSharesController < My::ApplicationController
  # My::ApplicationControllerがrequire_loginを定義済み
end
```

**悪い例:**
```ruby
class My::PeriodSharesController < ApplicationController
  before_action :require_login # 重複

  def require_login
    # My::ApplicationControllerと重複
  end
end
```

## 5. セキュリティとエラーハンドリング

### 5.1 適切な例外処理

**チェック項目:**
- [ ] 広範な`rescue StandardError`を使っていないか
- [ ] より具体的な例外クラスを指定できないか
- [ ] エラーをログに記録しているか

**良い例:**
```ruby
rescue ActiveRecord::RecordInvalid => e
  Rails.logger.error "Invalid record: #{e.message}"
  render json: { error: e.message }, status: :unprocessable_entity
```

**悪い例:**
```ruby
rescue StandardError => e
  # 全ての例外を握りつぶす
end
```

### 5.2 Strong Parameters

**チェック項目:**
- [ ] すべてのパラメータが`permit`されているか
- [ ] 不要なパラメータまで`permit`していないか

## 6. その他のベストプラクティス

### 6.1 無駄な処理の削減

**チェック項目:**
- [ ] 使われていない変数への代入がないか
- [ ] 結果を使わないメソッド呼び出しがないか
- [ ] 不要な`rescue`節がないか

**例:**
```ruby
# Before (無駄)
def time_zone_display
  ActiveSupport::TimeZone.find_tzinfo(time_zone) # 結果を使っていない
  "(UTC#{ActiveSupport::TimeZone[time_zone].formatted_offset}) #{time_zone}"
end

# After
def time_zone_display
  tz = ActiveSupport::TimeZone[time_zone]
  return time_zone unless tz

  "(UTC#{tz.formatted_offset}) #{time_zone}"
end
```

### 6.2 コメントの品質

**チェック項目:**
- [ ] コメントが「なぜ」を説明しているか（「何を」ではなく）
- [ ] TODOコメントに期限や担当者が書かれているか
- [ ] 古くなったコメントが残っていないか
