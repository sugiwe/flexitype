### 2. 新規キーマップ作成のバグ修正

**問題点:**
- キーマップ新規作成画面で「作成」ボタンを押しても反応しない
- サーバーログで `ROLLBACK` が発生していた

**原因調査:**
1. **Turbo 非対応**: [app/views/my/keymaps/new.html.slim:9](app/views/my/keymaps/new.html.slim#L9)
   - `form_with` に `local: true` が指定されていた
   - Rails 8 の Turbo 環境では `local: true` は不要（むしろ動作しない）

2. **空文字のDB保存エラー**: [app/models/keymap_set.rb:52](app/models/keymap_set.rb#L52)
   - `copy_default_keymap` メソッドが空文字をDBに保存しようとしていた
   - Layer 1 の L1-R1 で validation エラー（`character` は presence: true）
   - トランザクションが ROLLBACK され、キーマップセットも作成されず

**修正内容:**

#### form_with の修正
- [app/views/my/keymaps/new.html.slim:9](app/views/my/keymaps/new.html.slim#L9): `local: true` を削除
- Turbo による非同期送信を有効化

#### copy_default_keymap の修正
- [app/models/keymap_set.rb:52](app/models/keymap_set.rb#L52): 空文字をスキップするロジックを追加
```ruby
keymap_hash.each do |position, character|
  # 空文字の場合はスキップ（未設定として扱う）
  next if character.blank?

  keymaps.create!(...)
end
```

**結果:**
- ✅ 新規キーマップ作成が正常に動作
- ✅ デフォルトキーマップの設定済みキーのみがDBに保存される
- ✅ 未設定キーは保存されず、空欄として扱われる

## 学んだこと・気づき

### 1. デバッグ時のユーザーとの協力

**学んだこと:**
- ユーザーが具体的なファイルと行番号を指摘してくれることで、デバッグが大幅に効率化
- 今回、ユーザーが `typing_controller.js:448` や `keymap_editor_controller.js:132` を指摘
- さらに「数字練習時にレイヤー1のキーボードが表示される」という重要な情報を提供
- これにより、根本原因（`typing_controller.js:363` の `|| '-'`）を素早く特定できた

**今後の活かし方:**
- ユーザーフィードバックは非常に価値がある
- 特に「どの画面で」「どのような操作をした時に」「何が起きたか」という詳細情報が重要
- ログやエラーメッセージだけでなく、ユーザーの視点での動作確認が必須

### 2. フロントエンドとバックエンドの整合性

**学んだこと:**
- 今回の修正では、YAML（データ）、Ruby（サーバーサイド）、JavaScript（クライアントサイド）、Slim（ビュー）の全レイヤーで整合性を保つ必要があった
- 一箇所だけ修正しても、別のレイヤーで古い実装が残っていると問題が再発する
- 特に `|| '-'` のようなデフォルト値は、複数箇所に散らばりやすい

**ベストプラクティス:**
- Grep で全ファイルを検索し、関連する箇所をすべて洗い出す
- ヘルパーメソッドやUtility関数に集約し、DRYに保つ
- コミット時に関連ファイルを一緒に確認する

### 3. Rails 8 の Turbo による form_with の挙動変化

**学んだこと:**
- Rails 7 までは `form_with` に `local: true` を指定することで、従来型のフォーム送信（ページリロード）を実現していた
- Rails 8 + Turbo では、デフォルトで Turbo による非同期送信が有効
- `local: true` は不要（むしろ動作しない可能性がある）

**今後の対応:**
- Rails 8 のフォームは基本的に `form_with` をそのまま使う
- Turbo Frame や Turbo Stream を活用して、UX を向上させる
- 既存のフォームを見直し、`local: true` が残っていないか確認する

### 4. ActiveRecord の validation と transaction

**学んだこと:**
- `create!` メソッドは validation エラーで例外を発生させる
- トランザクション内で例外が発生すると、すべての変更が ROLLBACK される
- 今回、`copy_default_keymap` 内で空文字を `create!` しようとして失敗
- その結果、`keymap_set` 自体も作成されなかった

**対策:**
- `next if character.blank?` で事前に空データをスキップ
- または `create` メソッド（例外を発生させない）を使い、エラーハンドリングを明示的に行う
- トランザクション内では特に validation を意識する

### 5. コミット粒度の設計

**学んだこと:**
- 1つの大きな変更を適切な粒度に分割することで、レビューがしやすくなる

**技術的な学び:**

1. **フロントエンドとバックエンドの整合性**
   - YAML、Ruby、JavaScript、Slim の全レイヤーで一貫した実装が重要
   - デフォルト値（`|| '-'` など）は複数箇所に散らばりやすく、Grepで全検索が必須

2. **Rails 8 の Turbo による挙動変化**
   - `form_with` の `local: true` は不要（むしろ動作しない）
   - Turbo による非同期送信がデフォルト

3. **ActiveRecord の validation と transaction**
   - `create!` は validation エラーで例外を発生
   - トランザクション内では事前チェック（`next if character.blank?`）が重要

4. **DRY原則の実践**
   - 認証チェック: `logged_in?` による直接チェックで、`require_login` メソッドの重複を回避
   - レイアウトパーシャル: `_head.html.slim`、`_gtm_noscript.html.slim` で共通化

5. **技術的な判断と優先順位**
   - 動的OGP画像生成: ローカル環境で動作せず、静的画像で代替
   - ツイート文面とランディングページで結果が確認できるため、現時点では十分
