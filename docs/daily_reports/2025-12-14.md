### 1. 独自ドメインとSSL/HTTPS設定

#### Cloudflare設定

- **SSL/TLS暗号化モード**: Flexibleに設定

  - Cloudflare ↔ VPS間: HTTP
  - VPSではSSL証明書不要（Cloudflareが終端）

```yaml

  ssl: false  # CloudflareがSSL終端を担当するため
```

```ruby
config.assume_ssl = true   # プロキシ経由でSSL接続されていると仮定
config.force_ssl = true    # すべてのアクセスをHTTPSに強制
```

### 3. メール許可リスト（ALLOWED_EMAILS）のセキュア管理

#### 課題
- 当初、`config/deploy.yml` の `env.clear` セクションに `ALLOWED_EMAILS: ""` が記載されていた
- この設定ファイルはGit管理されているため、メールアドレスを直接記載するとセキュリティリスクがある

#### 解決策
`.kamal/secrets` ファイル（Git管理外）で管理：

**.kamal/secrets**（Git管理外）:
```bash
ALLOWED_EMAILS=user@gmail.com
```

**config/deploy.yml**（Git管理内）:
```yaml
env:
  secret:
    - RAILS_MASTER_KEY
    - FLEXITYPE_DATABASE_PASSWORD
    - ALLOWED_EMAILS  # ← 追加
  clear:
    DB_HOST: 153.120.65.157
    RAILS_LOG_LEVEL: info
    # ALLOWED_EMAILS: "" ← 削除
```

#### 環境変数の反映
```bash
bin/kamal app boot
```

このコマンドで `.kamal/secrets` から環境変数を読み込み、コンテナを再起動。

## 技術的な学び

### kamal-proxyのルーティング
- kamal-proxyは `Host` ヘッダーでルーティングを行う
- `host: typnix.com` 設定により、IPアドレス直接アクセスは404になる（正常な動作）
- ドメイン経由でのみアプリにアクセス可能

### CloudflareのSSL暗号化モード
- **Flexible**: Cloudflare ↔ ブラウザ間のみHTTPS（今回採用）
- **Full**: Cloudflare ↔ VPS間もHTTPS（VPSでSSL証明書が必要）
- **Full (strict)**: 有効なSSL証明書が必要

今回はVPSでSSL証明書を管理しない設計のため、Flexibleモードが最適。

### Kamalでの環境変数管理
- `env.secret`: `.kamal/secrets` から読み込む（Git管理外）
- `env.clear`: `config/deploy.yml` に直接記載（Git管理内）
- 機密情報は必ず `env.secret` で管理する

### Google Identity Servicesの認証フロー
- リダイレクトURIは実際には使用されない
- フロントエンドでIDトークンを取得し、`POST /auth/google` に送信
- ただし、Google Cloud Consoleでは設定が必須

## トラブルシューティング

### 問題1: Cloudflare SSL設定で接続不可
- **症状**: SSL/TLS設定を「Full」にすると https://typnix.com/ が開かない
- **原因**: VPS側でSSL証明書を用意していないため、Cloudflare→VPS間のHTTPS接続が失敗
- **解決**: SSL/TLS設定を「Flexible」に変更

### 問題2: ログイン後に「このメールアドレスは許可されていません」エラー
- **症状**: Google認証は成功するが、その後アクセス拒否される
- **原因**: `ALLOWED_EMAILS` が空文字列のまま
- **解決**: `.kamal/secrets` にメールアドレスを追加し、`bin/kamal app boot` で反映

### 4. Full SSL設定への移行（追加実装）

#### Flexible SSLの問題点に気づく
- Flexible SSL（Cloudflare↔VPS間がHTTP）は推奨されない構成
- `force_ssl = true` との組み合わせで無限リダイレクトのリスク
- セキュリティベストプラクティスではない

#### Full SSL（Let's Encrypt）への移行
**config/deploy.yml の変更:**
```yaml
proxy:
  ssl: true  # false から true に変更
  host: typnix.com
```

**デプロイ:**
```bash
bin/kamal deploy
```

kamal-proxyが自動的にLet's EncryptでSSL証明書を取得。

**Cloudflare設定:**
- SSL/TLS暗号化モード: Flexible → **Full** に変更

#### 結果
- ✅ エンドツーエンドで暗号化（ブラウザ→Cloudflare→VPS）
- ✅ Let's Encrypt証明書の自動取得・更新
- ✅ セキュリティベストプラクティスに準拠
