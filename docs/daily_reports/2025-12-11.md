### 2. Tailwind CSS v4ダークモード実装

#### 初期設定の苦戦
- `tailwind.config.js` の作成
- `darkMode: 'class'` の設定
- `app/assets/tailwind/application.css` に `@custom-variant dark (&:where(.dark, .dark *));` を追加
- 当初は正しいファイルパスが分からず、複数回の試行錯誤を実施

#### トラブルシューティング
- 404エラー（`GET http://localhost:3000/assets/tailwindcss net::ERR_ABORTED 404`）が発生
- 複数のアプローチを試行:
  - `@import "tailwindcss"` → 404エラー
  - `@tailwind base/components/utilities` → v4での非推奨警告
  - `@import "tailwindcss/preflight"` と `utilities` → 2つの404エラー
  - カスタムCSSに `!important` ルール追加 → 効果なし
  - 様々な `@variant` 構文を試行 → 認識されず

#### 解決策
- Tailwind CSS v4公式ドキュメントを確認
- 正しいファイルパス `app/assets/tailwind/application.css` を発見
- 正しい構文 `@custom-variant dark (&:where(.dark, .dark *));` を使用
- これにより `.dark\:*:where(.dark,.dark *)` セレクタが正しく生成された

## 学んだこと・気づき

### Tailwind CSS v4の仕組み
- `tailwindcss-rails` gem (v4.4.0) では、入力ファイルは `app/assets/tailwind/application.css`
- `@custom-variant` ディレクティブでカスタムバリアントを定義できる
- v4では `@tailwind` ディレクティブではなく `@import "tailwindcss"` を使用

### ダークモード実装のベストプラクティス
- ページ読み込み前の即座なテーマ適用でちらつきを防止
- LocalStorageで設定を永続化
- システム設定の変更を監視してリアルタイムで反映
- 将来の拡張を考慮した配列ベースのテーマ定義
