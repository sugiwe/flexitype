## 本日の作業概要

Day 19: Googleログイン機能の緊急バグ修正（Turbo対応・CSP競合解消）

## 発生した問題

朝の確認で、Googleログインボタンに3つの重大な問題が発生していることを発見:

1. **表示崩れ**: ボタンのアイコンが巨大に表示され、CSSが適用されていない
2. **ログイン失敗**: Google認証は成功するが、アプリに戻ってもログイン状態にならない
3. **Turbo問題**: トップページではボタンが表示されるが、他のページに移動するとボタンが消える

## 原因分析

### 1. CSP（Content Security Policy）とnonceの競合

**問題**:
- `config/initializers/content_security_policy.rb` でnonce生成を有効化していた
- nonceディレクティブを有効にすると `:unsafe_inline` が無効化される
- Google Identity Services (GIS) のインラインスクリプトがブロックされた

**ブラウザのコンソールエラー**:
```
Refused to execute inline script because it violates the following
Content Security Policy directive: "script-src 'self' https: 'nonce-xxx'".
```

**根本原因**:
```ruby
# config/initializers/content_security_policy.rb
config.content_security_policy_nonce_generator = ->(request) { request.session.id.to_s }
config.content_security_policy_nonce_directives = %w[script-src style-src]
# ↑ これがあると、Google の inline script が動かない
```

### 2. CSRF トークンの欠落

**問題**:
- サイドバーのインラインJavaScriptで `/auth/google` にPOSTリクエストを送信
- `X-CSRF-Token` ヘッダーが欠落していた
- Rails側で 422/403 エラーが発生

**エラー内容**:
```
ActionController::InvalidAuthenticityToken
Can't verify CSRF token authenticity
```

### 3. Turboのページキャッシュ問題

**問題**:
- Turboがページ遷移時にキャッシュからHTMLを復元
- Google Identity Services (GIS) の初期化処理が再実行されない
- ボタンのDOMは存在するが、イベントハンドラが消失

**発生フロー**:
1. トップページを読み込む → GIS初期化 → ボタン表示OK
2. 別のページに移動 → Turboがキャッシュから復元 → GIS未初期化 → ボタン消失
3. ページをリロード → GIS初期化 → ボタン表示OK

## 実装した解決策

### 1. CSP nonceの無効化

**修正内容**:
```ruby
# config/initializers/content_security_policy.rb

# FIXME: nonce生成を一時的に無効化（Googleログインとの競合を回避）
# config.content_security_policy_nonce_generator = ->(request) { request.session.id.to_s }
# config.content_security_policy_nonce_directives = %w[script-src style-src]
```

**理由**:
- nonce を無効化すると `:unsafe_inline` が有効になり、Googleのインラインスクリプトが動作する
- セキュリティレベルは若干下がるが、Googleログインとの両立を優先
- 将来的に、Google GISのnonce対応を検討する必要がある

### 2. CSRF トークンの追加

**修正内容**:
```javascript
// app/javascript/controllers/google_signin_controller.js

handleCredentialResponse(response) {
  const csrfToken = document.querySelector('meta[name="csrf-token"]').content

  fetch('/auth/google', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-CSRF-Token': csrfToken  // ← NEW!
    },
    body: JSON.stringify({ credential: response.credential })
  })
  .then(res => res.json())
  .then(data => {
    if (data.success) {
      window.location.href = data.redirect_url
    } else {
      alert('ログインに失敗しました: ' + (data.error || '不明なエラー'))
    }
  })
}
```

**効果**:
- Rails側のCSRF保護をパス
- 正常にログイン処理が完了するようになった

#### 3-1. Turbo対応の初期化処理

```javascript
connect() {
  // 既に初期化済みの場合はスキップ（重複初期化を防止）
  if (this.element.dataset.googleSigninInitialized === 'true') {
    return
  }

  // Turboのページ遷移後、GISが既に読み込まれているか確認
  if (window.google?.accounts?.id) {
    this.initializeGoogleSignIn()
  } else {
    // GISスクリプトの読み込みを待つ
    this.waitForGoogleScript()
  }
}
```

#### 3-2. GIS スクリプトの待機処理

```javascript
waitForGoogleScript() {
  // GISが読み込まれるまで待機（最大5秒）
  let attempts = 0
  const maxAttempts = 50 // 50 * 100ms = 5秒

  const checkInterval = setInterval(() => {
    if (window.google?.accounts?.id) {
      clearInterval(checkInterval)
      this.initializeGoogleSignIn()
    } else if (++attempts >= maxAttempts) {
      clearInterval(checkInterval)
      console.error('Google Identity Services の読み込みに失敗しました')
    }
  }, 100)
}
```

#### 3-3. 重複初期化の防止

```javascript
initializeGoogleSignIn() {
  const buttonElement = this.element.querySelector('.g_id_signin')
  if (!buttonElement) {
    console.error('Google Sign-In button element not found')
    return
  }

  // Google Identity Servicesの初期化（先に実行）
  window.google.accounts.id.initialize({
    client_id: this.clientIdValue,
    callback: this.handleCredentialResponse.bind(this),
    auto_select: false
  })

  // 初期化後にボタンをレンダリング
  window.google.accounts.id.renderButton(buttonElement, { ... })

  // 初期化完了フラグをセット
  this.element.dataset.googleSigninInitialized = 'true'
}

disconnect() {
  // クリーンアップ（必要に応じて）
  this.element.dataset.googleSigninInitialized = 'false'
}
```

**効果**:
- Turboのページ遷移後も、コントローラの `connect()` が呼ばれて再初期化される
- 重複初期化を防止し、パフォーマンスを最適化
- ボタンが常に表示され続けるようになった

## 技術的なポイント

### CSP（Content Security Policy）の理解

**CSP の基本**:
- ブラウザに「どのスクリプトやスタイルを読み込んでいいか」を指示するセキュリティ機能
- インラインスクリプト（`<script>` タグ内のコード）はデフォルトでブロックされる
- `:unsafe_inline` を許可するか、nonce を使って個別に許可する必要がある

**nonce ディレクティブの仕組み**:
```ruby
# config/initializers/content_security_policy.rb
policy.script_src :self, :https, :unsafe_inline  # インラインスクリプトを許可

# しかし、nonce ディレクティブを有効にすると :unsafe_inline が無効化される
config.content_security_policy_nonce_directives = %w[script-src style-src]
```

**Google GIS との競合**:
- Google Identity Services は内部でインラインスクリプトを使用
- nonce を有効にすると、これらのスクリプトがブロックされる
- 現時点では nonce を無効化して `:unsafe_inline` で対応

### Turbo と外部ライブラリの統合

**Turbo の動作**:
- ページ遷移時にキャッシュからHTMLを復元
- `<script>` タグは再実行されない
- イベントハンドラは消失する

**Stimulus コントローラの利点**:
- `connect()` メソッドがDOMに接続されるたびに呼ばれる
- Turboのページ遷移後も自動的に再初期化される
- 外部ライブラリとの統合に最適

**重複初期化の防止**:
- `data-*-initialized` フラグで状態を管理
- `connect()` 内でフラグをチェックし、初期化済みならスキップ
- `disconnect()` でフラグをリセット

### CSRF 保護

**Rails の CSRF 保護**:
- すべての POST/PATCH/DELETE リクエストで CSRF トークンをチェック
- `<meta name="csrf-token">` タグにトークンが埋め込まれている
- Fetch API で POST する場合は、手動でヘッダーに追加する必要がある

**実装パターン**:
```javascript
const csrfToken = document.querySelector('meta[name="csrf-token"]').content
fetch('/path', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-CSRF-Token': csrfToken  // ← 必須
  },
  body: JSON.stringify(data)
})
```

## 学んだこと

### セキュリティ機能の二面性

- CSP や nonce は重要なセキュリティ機能だが、外部ライブラリと競合することがある
- セキュリティと機能性のバランスを取る必要がある
- 一時的な妥協案（nonce無効化）を採用し、将来的な改善を計画

### ブラウザのコンソールエラーの重要性

- 表面的な問題（アイコンが大きい）の裏に、深刻な問題（CSP違反）が隠れていた
- コンソールエラーを丁寧に読むことで、根本原因を特定できた
- ブラウザの開発者ツールはデバッグの最強の味方

### Turbo と外部ライブラリの統合パターン

- Stimulus コントローラを使うことで、Turbo と外部ライブラリを統合できる
- `connect()` / `disconnect()` のライフサイクルを理解することが重要
- 重複初期化の防止など、細かい配慮が必要

### Rails の設定変更時の注意点

- `config/initializers/` 配下のファイルを変更した場合は、サーバーの再起動が必要
- 再起動を忘れると、変更が反映されずに混乱する
- デプロイ時も同様に、設定変更はプロセス再起動後に反映される
