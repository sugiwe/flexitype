### 2. タイピング練習履歴機能の実装（Phase 4完了）

**目的:**
- ログインユーザーがタイピング練習の履歴を閲覧できる機能
- 無料ユーザーは50件の履歴を保持（自動クリーンアップ）
- 将来の課金ユーザー向けに拡張可能な設計

**実装内容:**

#### データベース設計
- **`TypingSession`モデルの作成**
  - フィールド:
    - `user_id` (references, not null)
    - `category` (string)
    - `lesson_id` (string)
    - `lesson_name` (string)
    - `word_count` (integer, default: 0, not null)
    - `correct_count` (integer, default: 0, not null)
    - `mistake_count` (integer, default: 0, not null)
    - `accuracy` (decimal, precision: 5, scale: 2)
    - `duration_seconds` (integer)
    - `completed_at` (datetime)
  - インデックス:
    - `[user_id, completed_at]`（降順）- 履歴一覧取得用
    - `[user_id, created_at]`（降順）- 古い履歴削除用

- **`User`モデルに`history_limit`カラム追加**
  - デフォルト値: 50
  - null: false
  - 将来的に課金ユーザーは増やせる設計

#### 自動クリーンアップ機能
- `TypingSession`作成後、`history_limit`を超えた古い履歴を自動削除
- `after_create`コールバックで実装
- パフォーマンスを考慮したインデックス設計

```ruby
class TypingSession < ApplicationRecord
  after_create :cleanup_old_sessions

  private
  def cleanup_old_sessions
    user.cleanup_old_typing_sessions
  end
end

class User < ApplicationRecord
  def cleanup_old_typing_sessions
    sessions = typing_sessions.order(created_at: :desc)
    sessions.offset(history_limit).destroy_all
  end
end
```

#### Stimulus Controller拡張（typing_controller.js）
- 練習完了時に自動的に履歴を保存
- `loggedInValue`で認証状態を判定（ログイン時のみ保存）
- CSRF対策（`X-CSRF-Token`ヘッダー）
- エラーハンドリング（コンソールにログ出力）

```javascript
async saveHistory(accuracy, durationSeconds) {
  if (!this.loggedInValue) return; // ログインしていない場合は保存しない

  try {
    const response = await fetch('/history', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'X-CSRF-Token': document.querySelector('meta[name="csrf-token"]').content
      },
      body: JSON.stringify({
        session: {
          category: this.lessonInfoValue.category_key,
          lesson_id: this.lessonInfoValue.lesson_id,
          lesson_name: this.lessonInfoValue.lesson_name,
          word_count: this.words.length,
          correct_count: this.words.length * this.words.reduce((sum, word) => sum + word.length, 0) - this.mistakeCount,
          mistake_count: this.mistakeCount,
          accuracy: accuracy,
          duration_seconds: durationSeconds
        }
      })
    })
    if (!response.ok) {
      console.error('Failed to save history:', await response.text())
    }
  } catch (error) {
    console.error('Error saving history:', error)
  }
}
```

## 📝 学んだこと・気づき

### データベース設計
- **インデックスの重要性**:
  - `[user_id, completed_at]`: 履歴一覧取得を高速化
  - `[user_id, created_at]`: 古い履歴削除を高速化
  - 降順インデックス（`order: { created_at: :desc }`）で`LIMIT`と`OFFSET`を効率化

### ActiveRecordのコールバック
- `after_create`コールバックで自動クリーンアップを実装
- パフォーマンスへの影響を考慮し、必要最小限の処理に留める
- トランザクション内で実行されるため、エラー時はロールバックされる

### Kaminariの使い方
- `page(params[:page]).per(20)`: ページネーション設定
- `= paginate @sessions`: ビューでページネーションリンク表示
- デフォルトでBootstrap風のスタイル（Tailwindでカスタマイズ可能）

### Strong Parametersと動的ハッシュ
- レイヤーごとの動的ハッシュを許可する場合、明示的に各レイヤーを列挙
- `permit!`は避けるべきだが、やむを得ない場合はコメントで理由を明記

### Kamalデプロイのトラブルシューティング

- マイグレーションは`kamal app exec 'bin/rails db:migrate'`で直接実行可能
- デプロイ後のバージョン確認: `kamal app version`
