### 1. テスト戦略の策定とドキュメント化

#### テスト哲学の確立

Day 25で以下のテスト方針を確立しました：

1. **「あるべき姿」のテストを書く**: テストが通らない場合、実装を修正してテストに合わせる（テストを歪めない）
   - 例: エラーメッセージが英語のままなら、日本語翻訳を追加する
   - テストを通すためにテストの内容を歪めるのは本末転倒

2. **プラグマティックなアプローチ**: 80-90%のテストが通る状態を優先し、複雑なテストは後回し
   - 複雑なテストは `skip` でスキップし、TODOコメントで理由と解決策を記録
   - 数%の部分が通らなくて先に進めないより、まず80-90%を完成させる

3. **TDD (Test-Driven Development)**: 理想的な動作を先にテストで定義し、実装をそれに合わせる

#### 技術的課題の解決

**問題:** `Faker::Number.unique` が100回でリトライ制限に到達

**解決策:** `sequence()` を使った連番生成に変更

```ruby
# Before (エラー)
name { "キーマップ#{Faker::Number.unique.number(digits: 2)}" }

# After (修正)
sequence(:name) { |n| "テストキーマップ#{n}" }
```

### 5. 重要なテストの実装例

#### WPM計算のテスト

```ruby
describe "WPM計算" do
  it "typed_charsとduration_secondsからWPMを自動計算すること" do
    lesson_record = build(:lesson_record, typed_chars: 500, duration_seconds: 60)
    lesson_record.send(:calculate_wpm)
    # CPM = (500 / 60) * 60 = 500
    # WPM = 500 / 5 = 100
    expect(lesson_record.wpm).to eq(100)
  end
end
```

#### グレード判定のテスト

```ruby
describe "グレード判定" do
  context "伝説のカワウソ級" do
    it "正答率98%以上、WPM 80以上で「伝説のカワウソ」になること" do
      lesson_record = build(:lesson_record, :legendary)
      lesson_record.send(:calculate_wpm)
      lesson_record.send(:calculate_grade)
      expect(lesson_record.grade).to eq("伝説のカワウソ")
    end
  end
end
```

### 2. プラグマティックなアプローチの重要性

**問題:** `active_keymap_set_id` NOT NULL制約でテストが複雑化

**解決策:** 80-90%のテストを先に完成させ、残りはTODOで管理

```ruby
it "一意であること" do
  # TODO: createを使うテストは active_keymap_set の制約で一旦スキップ
  # 解決策: FactoryBotのカスタム戦略 or User modelリファクタリング
  skip "createを使うテストは active_keymap_set の制約で一旦保留"
end
```

**効果:**
- 完全を目指して0%より、80%を先に完成させる方が建設的
- TODOコメントで「なぜスキップしたか」「どう解決するか」を明記
- 将来の自分や他の開発者への配慮

### 3. FactoryBotのベストプラクティス

#### `build()` vs `create()`

- `build()` - DB保存なし、バリデーションテスト向け
- `create()` - DB保存あり、スコープ・一意性制約テスト向け

#### `sequence()` の活用

`Faker::Number.unique` はリトライ制限があるため、一意な値には `sequence()` を使う:

```ruby
sequence(:name) { |n| "テストキーマップ#{n}" }
sequence(:slug) { |n| "test-keymap-#{n}" }
```

#### `trait` による多様なシナリオ

```ruby
factory :lesson_record do
  # ...

  trait :legendary do
    accuracy { 99.0 }
    typed_chars { 800 }
    duration_seconds { 60 }
  end
end

# 使用例
lesson_record = build(:lesson_record, :legendary)
```

---

### 4. privateメソッドのテスト

Railsのコールバック（`before_save`, `after_create` など）はprivateメソッドとして実装されることが多いです。

`send(:method_name)` を使えば、privateメソッドを直接テストできます:

```ruby
lesson_record = build(:lesson_record, typed_chars: 500, duration_seconds: 60)
lesson_record.send(:calculate_wpm)  # private メソッドを直接呼び出し
expect(lesson_record.wpm).to eq(100)
```

### 5. モデルテスト vs システムテストの使い分け

| テスト種類 | 目的 | 速度 | 範囲 | Typnixでの例 |
|---------|------|------|------|------------|
| **モデルテスト** | データ層のロジック検証 | ⚡ 速い | 1モデル | WPM計算が正しいか？ |
| **システムテスト** | ユーザー体験の検証 | 🐌 遅い | アプリ全体 | タイピング練習→結果保存→履歴表示が動くか？ |

**モデルテスト:**
- バリデーション、ビジネスロジック、メソッドの単体テスト
- 高速（0.35秒で158 examples実行）
- 今回実装完了（81%完成度）

**システムテスト:**
- ユーザーの実際の操作フローを再現
- 遅い（ブラウザ起動が必要）
- 次回実装予定
