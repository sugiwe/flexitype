#### テスト哲学の確立

Day 25で以下のテスト方針を確立しました：

1. **「あるべき姿」のテストを書く**: テストが通らない場合、実装を修正してテストに合わせる（テストを歪めない）

   - 数%の部分が通らなくて先に進めないより、まず80-90%を完成させる

3. **TDD (Test-Driven Development)**: 理想的な動作を先にテストで定義し、実装をそれに合わせる

### 5. 重要なテストの実装例

#### WPM計算のテスト

```ruby
describe "WPM計算" do
  it "typed_charsとduration_secondsからWPMを自動計算すること" do
    lesson_record = build(:lesson_record, typed_chars: 500, duration_seconds: 60)
    lesson_record.send(:calculate_wpm)
    # CPM = (500 / 60) * 60 = 500
    # WPM = 500 / 5 = 100
    expect(lesson_record.wpm).to eq(100)
  end
end
```

#### グレード判定のテスト

```ruby
describe "グレード判定" do
  context "伝説のカワウソ級" do
    it "正答率98%以上、WPM 80以上で「伝説のカワウソ」になること" do
      lesson_record = build(:lesson_record, :legendary)
      lesson_record.send(:calculate_wpm)
      lesson_record.send(:calculate_grade)
      expect(lesson_record.grade).to eq("伝説のカワウソ")
    end
  end
end
```

**解決策:** 80-90%のテストを先に完成させ、残りはTODOで管理

### 3. FactoryBotのベストプラクティス

#### `build()` vs `create()`

- `build()` - DB保存なし、バリデーションテスト向け
- `create()` - DB保存あり、スコープ・一意性制約テスト向け

#### `sequence()` の活用

`Faker::Number.unique` はリトライ制限があるため、一意な値には `sequence()` を使う:

```ruby
sequence(:name) { |n| "テストキーマップ#{n}" }
sequence(:slug) { |n| "test-keymap-#{n}" }
```

#### `trait` による多様なシナリオ

```ruby
factory :lesson_record do
  # ...

  trait :legendary do
    accuracy { 99.0 }
    typed_chars { 800 }
    duration_seconds { 60 }
  end
end

# 使用例
lesson_record = build(:lesson_record, :legendary)
```

---

### 4. privateメソッドのテスト

Railsのコールバック（`before_save`, `after_create` など）はprivateメソッドとして実装されることが多いです。

`send(:method_name)` を使えば、privateメソッドを直接テストできます:

```ruby
lesson_record = build(:lesson_record, typed_chars: 500, duration_seconds: 60)
lesson_record.send(:calculate_wpm)  # private メソッドを直接呼び出し
expect(lesson_record.wpm).to eq(100)
```

#### active_keymap_set制約問題の解決

**問題:**
- システムテスト実行時に`PG::NotNullViolation`エラーが発生
- `User.from_google`の`first_or_create`が内部で`create!`を呼び出す
- `after_create`コールバック実行前にNOT NULL制約チェックが走る

**根本原因の分析:**
Railsのトランザクション順序:
1. `INSERT`（データベースへの保存）
2. NOT NULL制約チェック ← ここでエラー発生
3. `after_create`コールバック（`active_keymap_set`を設定）

**解決策:**
1. **マイグレーション作成:** `active_keymap_set_id`のNOT NULL制約を削除
2. **Userモデル修正:** `belongs_to :active_keymap_set, optional: true`
3. **カスタムバリデーション追加:** 作成後に`active_keymap_set`が必須であることを確認
   ```ruby
   def must_have_active_keymap_set_after_creation
     return if new_record? # 新規作成時はチェックしない
     return if active_keymap_set_id.present?
     errors.add(:active_keymap_set, "は必須です")
   end
   ```
4. **FactoryBot修正:** `after_create`フックを削除（モデルのコールバックに任せる）

**影響:**
- ✅ 本番環境でも`User.from_google`が正常に動作
- ✅ システムテストでユーザー作成が可能に
- ✅ モデルテストの30個のスキップもこれで解消可能（別ブランチで対応予定）
