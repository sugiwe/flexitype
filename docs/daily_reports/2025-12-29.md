### 1. パイプ文字（|）のキーマップ設定バグ修正

**背景:**
- キーマップ設定でパイプ文字「|」が設定できず、ブランクになってしまう
- 「|」が2段表示の区切り文字として使われているため、単体文字と区別できていなかった

**実装内容:**

#### 修正ファイル（3箇所）:

1. **`app/helpers/application_helper.rb`**
   - `split_key_display` メソッド修正
   - `char.length > 1` で区切り文字判定（単体の「|」は区切らない）
   - 後方互換性コメント追加

2. **`app/javascript/controllers/keymap_editor_controller.js`**
   - `saveKeymap()` メソッド修正
   - 保存時は空白のみを区切り文字として使用
   - 後方互換性のため、既存の「|」区切りも読み込み可能

3. **`app/javascript/controllers/typing_controller.js`**
   - `findKeysForChar()` メソッド修正
   - 表示時は `char.length > 1` で区切り文字判定

**技術的なポイント:**
- 新規保存: 空白区切りのみ（例: `1 !`）
- 既存データ: 「|」区切りも読み込み可能（後方互換性）
- 単体の「|」: `length === 1` で判定し、区切り文字として扱わない

#### 2-2. DRY原則に基づくリファクタリング

`LessonRecordsController` と `My::HistoryController` で記録保存ロジックが重複していたため、Concernパターンで共通化。

**ファイル:** `app/controllers/concerns/lesson_record_creation.rb`

```ruby
module LessonRecordCreation
  extend ActiveSupport::Concern

  private

  def create_lesson_record_for(user)
    @lesson_record = user.lesson_records.build(lesson_record_params)
    @lesson_record.completed_at = Time.current

    if @lesson_record.save
      render json: { success: true, message: "練習履歴を保存しました", lesson_record_id: @lesson_record.id }
    else
      render json: { success: false, errors: @lesson_record.errors.full_messages }, status: :unprocessable_entity
    end
  end

  def lesson_record_params
    params.require(:lesson_record).permit(
      :lesson_id, :lesson_name, :word_count, :correct_count,
      :mistake_count, :accuracy, :duration_seconds, :typed_chars
    )
  end
end
```

#### 2-3. 公開エンドポイント作成

**ファイル:** `app/controllers/lesson_records_controller.rb`

```ruby
class LessonRecordsController < ApplicationController
  include LessonRecordCreation

  def create
    user = logged_in? ? current_user : User.find_by!(username: "guest")
    create_lesson_record_for(user)
  end
end
```

**ルーティング:**

### 4. コントローラー命名の統一

**背景:**
- `My::HistoryController` vs `Admin::LessonRecordsController`
- 同じ役割（練習履歴一覧）なのに名前が異なる
- コードの一貫性が損なわれる

**検討した選択肢:**

**Option 1: コントローラー名を統一、URLはそのまま（採用）**
- `My::HistoryController` → `My::LessonRecordsController`
- URL: `/my/history`（変更なし）
- ルーティング: `controller: "lesson_records"` オプション使用

**Option 2: URLも変更**
- `/my/history` → `/my/lesson_records`
- コントローラー名と完全一致

**Option 3: 現状維持**
- 変更なし

**決定:** Option 1 を採用

**理由:**
- バックエンドコードが統一される（`lesson_records` で一貫）
- ユーザー向けURLは洒落た感じを保てる（`/my/history`）
- 将来的にURL変更も容易（影響範囲は5ファイルのみ）

**実装内容:**

1. **ファイル名変更:**
   - `app/controllers/my/history_controller.rb` → `app/controllers/my/lesson_records_controller.rb`

2. **クラス名変更:**
   - `My::HistoryController` → `My::LessonRecordsController`

3. **ルーティング修正:**
   ```ruby
   resources :history, only: [ :index, :create ], controller: "lesson_records"
   # /my/history (URL), My::LessonRecordsController (コントローラー)
   ```

4. **ビューディレクトリ名変更:**
   - `app/views/my/history/` → `app/views/my/lesson_records/`
   - **重要:** Railsの規約上、コントローラー名とビューディレクトリ名は一致する必要がある
   - この変更を忘れると406エラーが発生

**影響範囲:**
- ルーティング: 1箇所
- ビューリンク: 5ファイル（将来的にURLを変更する場合のみ影響）

## 学んだこと・気づき

### 1. 区切り文字判定の工夫

パイプ文字のバグ修正で、「区切り文字」と「単体の文字」を区別する方法として `char.length > 1` という判定を採用しました。

**利点:**
- シンプルで分かりやすい
- パフォーマンスも良好
- 正規表現よりも可読性が高い

**後方互換性の確保:**
- 既存データの「|」区切りも読み込み可能
- 新規保存は空白区切りのみ
- 段階的な移行が可能

### 2. Concernパターンの活用

今回、`LessonRecordCreation` Concernを作成し、コードの重複を解消しました。

**メリット:**
- DRY原則の徹底
- テストが容易（Concernのみテストすれば両方のコントローラーが保証される）
- 保守性の向上（変更箇所が1箇所のみ）

**Rails way:**
- `app/controllers/concerns/` ディレクトリに配置
- `extend ActiveSupport::Concern` で拡張
- `private` メソッドで共通ロジックを定義

### 3. ゲストユーザーパターンの設計

未ログインユーザーを「ゲストユーザー」として扱うパターンは、以下のメリットがあります：

**メリット:**
1. スキーマ変更不要（`user_id` が nullable でなくても動作）
2. コード変更が最小限（既存の `user.lesson_records.build` がそのまま使える）
3. 管理画面で「未ログインユーザー」として表示できる

**注意点:**
- ゲストユーザーは削除しないこと（マイグレーションにコメント記載）
- キーマップは設定できない想定（問題なし）

### 4. Railsの規約の重要性

`My::HistoryController` → `My::LessonRecordsController` に変更した際、ビューディレクトリ名も変更する必要がありました。

**Railsの規約:**
- コントローラー名: `My::LessonRecordsController`
- ビューディレクトリ: `app/views/my/lesson_records/`
- この一致が崩れると、406エラーが発生

**教訓:** コントローラー名を変更する際は、ビューディレクトリ名も忘れずに変更する。

### 5. 共通パーシャルの威力

今回、`shared/_lesson_records_table.html.slim` を作成し、3箇所で再利用しました。

**DRY化の効果:**
- 管理者ダッシュボード: 89行削減
- コード重複: 完全に解消
- UI一貫性: すべてのページで同じ表示を保証

**設計のポイント:**
- `local_assigns[:show_user]` で条件分岐
- `show_pagination` オプションでページネーション制御
- PC版とモバイル版の両方に対応

### 6. ルーティングの柔軟性

`controller:` オプションを使うことで、URLとコントローラー名を分離できます。

```ruby
resources :history, only: [ :index, :create ], controller: "lesson_records"
# URL: /my/history
# Controller: My::LessonRecordsController
```

**メリット:**
- ユーザー向けURLを洒落た感じに保てる
- バックエンドコードは統一的な命名
- 両方のバランスを取れる
