## 実装した機能

### 1. KeymapSet モデルの実装（複数キーマップ管理の基盤）

**目的**: ユーザーが複数のキーマップを管理できるようにする基盤を整備

**実装内容**:
- `KeymapSet` モデルと `KeymapLayer` モデルの作成
- データベース設計の変更（Keymap → KeymapSet + KeymapLayer）
- マイグレーション実装（既存データを新構造に移行）
- RESTful なルーティング設計（`/my/keymaps`）

**データベース構造**:
```ruby
# KeymapSet（キーマップセット）
- name: string（キーマップ名）
- description: text（説明）
- user_id: references User
- is_public: boolean（公開設定、将来実装）
- share_token: string（共有トークン、将来実装）

# KeymapLayer（各レイヤーのキー配置）
- keymap_set_id: references KeymapSet
- layer: integer (0-5)
- key_position: string（例: "L0-R0"）
- character: string（割り当てられた文字）
```

**マイグレーション**:
- 既存の Keymap データを KeymapSet + KeymapLayer に移行
- 各ユーザーに「デフォルト」という名前の KeymapSet を作成
- データの整合性を保証（トランザクション内で処理）

**URL 設計**:
```
GET    /my/keymaps          # キーマップ一覧（将来実装）
GET    /my/keymaps/1/edit   # キーマップ編集
PATCH  /my/keymaps/1        # キーマップ更新
DELETE /my/keymaps/1        # デフォルトに戻す
```

#### 9-4. CSP トラブルシューティング（インラインスタイルのブロック）

**問題**: CSP 有効化後、キーボードグリッドレイアウトが縦並びに崩れた

**原因**:
- CSP の nonce ディレクティブを有効化すると、`:unsafe_inline` が無効化される
- `style="grid-template-columns: repeat(6, 3.5rem);"` のようなインラインスタイルがブロックされる
- Tailwind CSS は基本的に影響を受けないが、`style=` 属性によるインラインスタイルは CSP でブロックされる

**CSP の仕組み**:
```ruby
# config/initializers/content_security_policy.rb
policy.style_src :self, :https, :unsafe_inline  # インラインスタイルを許可

# しかし、nonce ディレクティブを有効にすると :unsafe_inline が無効化される
config.content_security_policy_nonce_directives = %w[script-src style-src]
```

**解決策**: インラインスタイルを外部 CSS クラスに移行
1. `app/assets/stylesheets/application.css` にカスタムクラスを追加
   ```css
   .keyboard-grid-6col {
     grid-template-columns: repeat(6, 3.5rem);
   }
   ```
2. ビューファイルのインラインスタイルをクラスに置換
   - Before: `.grid.gap-1.5 style="grid-template-columns: repeat(6, 3.5rem);"`
   - After: `.grid.gap-1.5.keyboard-grid-6col`

**影響を受けたファイル**:
- `app/views/my/keymaps/edit.html.slim` (6/10/12/13/14列グリッド)
- `app/views/practices/show.html.slim` (6列グリッド)

**学び**:
- **Tailwind CSS は影響を受けない**: Tailwind のユーティリティクラス（`flex`, `grid`, `gap-1.5` など）は外部 CSS なので CSP の影響を受けない
- **インラインスタイル（`style=` 属性）は CSP でブロックされる**: セキュリティのため、`style=` 属性を使わず CSS クラスを使うべき
- **nonce ディレクティブと `:unsafe_inline` の関係**: nonce を有効にすると `:unsafe_inline` が無効化されるため、インラインスタイルは nonce 属性が必要になる
