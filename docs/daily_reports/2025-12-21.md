### 8. アーキテクチャ改善 Phase 1: Lessonから冗長なフラグを削除

**背景**:
カテゴリーとレッスンで同じ権限フラグ（`requires_login`, `premium`）を持っており、データの矛盾が発生する可能性があった。

**問題点**:
- カテゴリーが `requires_login: true` だけど、レッスンが `requires_login: false` の場合、矛盾が発生
- URL直打ちでアクセスできてしまう可能性

**解決策**:
- `lessons` テーブルから `requires_login` と `premium` カラムを削除
- Lesson モデルで `delegate :requires_login, :premium, to: :category` を使用してカテゴリーの設定を継承
- レッスン管理フォームから該当フィールドを削除
- My::LessonsController の Strong Parameters を簡素化
- スコープをカテゴリーテーブル参照に変更（`joins(:category).where(categories: { premium: false })`）

**効果**:
- データの一貫性が保証される
- カテゴリー単位での権限管理がシンプルに
- 「カテゴリーは有料だけどレッスンは無料」のような矛盾が防止される

### 9. アーキテクチャ改善 Phase 2: Categoryにpublishedフラグを追加

**背景**:
新規カテゴリー作成時、レッスンが0件でもホームページに表示されてしまい、ユーザー体験が良くなかった。

**解決策**:
- `categories` テーブルに `published` カラムを追加（デフォルト: true, null: false）
- Category モデルに `published` スコープを追加
- カテゴリー管理フォームに「公開する」チェックボックスを追加
- HomeController で `Category.published.ordered` でフィルタリング
- 既存カテゴリーは全て `published: true` に設定（マイグレーション内で実行）

**運用フロー**:
1. カテゴリー作成時は `published: false` で作成
2. レッスンを複数追加
3. 準備ができたら `published: true` に変更して公開

**効果**:
- レッスン準備中のカテゴリーを非表示にできる
- 明示的な公開制御が可能
- ユーザーに完成したコンテンツのみ提供できる

## 🔍 技術的な学び

### 1. JSONB型の活用

PostgreSQLのJSONB型を使うことで、配列データを柔軟に保存できた。フォームとの連携では、改行区切りテキストと配列の相互変換が必要。

```ruby
# Strong Parametersでの変換処理
if permitted_params[:items].is_a?(String)
  permitted_params[:items] = permitted_params[:items].split("\n").map(&:strip).reject(&:blank?)
end
```

### 2. ActiveRecordスコープの活用

権限管理を `visible_to` スコープに集約することで、コントローラがシンプルになった。

```ruby
scope :visible_to, ->(user) {
  if user&.admin?
    all
  else
    left_joins(:user).where(
      "lessons.user_id = :user_id OR lessons.is_public = true OR users.admin = true",
      user_id: user&.id
    ).distinct
  end
}
```

### 3. Rails wayなアーキテクチャ

サービスオブジェクトを削除し、モデル・コントローラ・ビューの責務を明確に分離することで、保守性が向上した。

### 4. ハイブリッドアプローチの有効性

管理者と一般ユーザーで別々のCRUDを作るのではなく、権限チェックで動作を分岐させる設計により:
- コードの重複を削減
- 将来的な拡張が容易
- テストがシンプル

## 🐛 遭遇したエラーと解決策

### 1. Duplicate index エラー

**エラー内容**:
```
PG::DuplicateTable: ERROR: relation "index_lessons_on_category_id" already exists
```

**原因**: `t.references :category` が自動的にインデックスを作成するのに、手動で `add_index :lessons, :category_id` を追加していた

**解決**: 手動インデックスを削除

### 2. 日本語parameterizeの問題

**問題**: `"基礎練習".parameterize.underscore` が空文字列を返し、全カテゴリーが同じキーになってしまった

**解決**: カテゴリーキーを `"category_#{category.id}"` に変更（安定したユニークキー）

### 3. User has_many :lessons の欠落

**エラー内容**:
```
NoMethodError: undefined method 'lessons' for an instance of User
```

**原因**: Userモデルに `has_many :lessons` が定義されていなかった

**解決**: 関連を追加

### 4. 本番環境でのレッスンデータ消失

**問題**: 本番環境にデプロイ後、全てのレッスンが表示されなくなった

**原因**:
- マイグレーション（`rails db:migrate`）でテーブルは作成された
- しかし、YAMLからDBへのデータ移行スクリプトを実行していなかった
- 開発環境では手動で `rails runner` を実行していたが、本番環境で忘れていた

**解決手順**:
1. Rakeタスクとして移行スクリプトを作成（`lib/tasks/migrate_lessons_from_yaml.rake`）
2. コミット・プッシュして再デプロイ
3. Kamal経由でRakeタスクを実行: `kamal app exec --roles=web 'bin/rails lessons:migrate_from_yaml'`
4. 6カテゴリー、16レッスンを正常に復旧

**教訓**:
- DB構造変更（マイグレーション）とデータ移行は別物
- 本番デプロイ時のチェックリストに「データ移行スクリプト実行」を追加すべき
- 重要なデータ移行はRakeタスク化して、デプロイ手順書に明記する
