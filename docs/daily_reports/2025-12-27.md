#### 技術的課題と解決策

##### 課題1: Keymap Factoryのカラム名誤り

**問題:**
```ruby
# Before (エラー)
factory :keymap do
  position { "L0-R0" }  # NoMethodError: undefined method 'position='
end
```

**原因:** カラム名は`key_position`だが、`position`を使っていた

**解決策:**
```ruby
# After (修正)
factory :keymap do
  key_position { "L0-R0" }  # ✅
end
```

##### 課題2: Keymap Factoryのuser_id制約

**問題:**
```ruby
factory :keymap do
  association :keymap_set
  # user_id が NULL でエラー
end
```

**原因:** `Keymap`テーブルには`user_id NOT NULL`制約があるが、FactoryBotで設定していなかった

**解決策:**
```ruby
factory :keymap do
  association :keymap_set
  user { keymap_set.user }  # keymap_setからuserを継承
end
```

##### 課題3: Keymapの重複作成エラー

**問題:**
```ruby
# Before (エラー)
create(:keymap, :key_h, keymap_set: keymap_set)
# ActiveRecord::RecordInvalid: バリデーションに失敗しました: Key position はすでに存在します
```

**原因:** `KeymapSet`は作成時に`after_create :copy_default_keymap`コールバックで全てのキー（48 positions × 6 layers = 288個）を自動生成する

**調査:**
```ruby
Keymap.where(keymap_set_id: keymap_set.id).count
# => 288 (既に全てのキーが存在)
```

**解決策:** 新規作成ではなく、既存のKeymapを更新する方針に変更
```ruby
# After (修正)
keymap_set.keymaps.find_by(layer: 0, key_position: "L2-R0").update(character: "h")
keymap_set.keymaps.find_by(layer: 0, key_position: "L0-R2").update(character: "e")
# ...
```

##### 課題4: Seleniumドライバーでのログイン処理

**問題:**
```ruby
# Before (エラー)
def login_as_user(user = nil)
  user ||= create(:user)
  page.driver.post "/test/sessions", user_id: user.id
  # NoMethodError: undefined method 'post' for #<Capybara::Selenium::Driver>
end
```

**原因:** `page.driver.post`は`rack_test`ドライバーでしか動作しない。`js: true`テストでは`selenium_chrome_headless`ドライバーが使われる

**解決策:** ドライバー自動判定 + GET経由のセッション設定
```ruby
# After (修正)
def login_as_user(user = nil)
  user ||= create(:user)

  if page.driver.is_a?(Capybara::RackTest::Driver)
    # rack_test: POSTでセッション設定（速い）
    page.driver.post "/test/sessions", user_id: user.id
  else
    # Selenium: GET経由でセッション設定（ブラウザ互換）
    visit "/test/sessions?user_id=#{user.id}"
  end

  user
end
```

**追加実装:** TestSessionsController#show
```ruby
# app/controllers/test_sessions_controller.rb
def show
  user_id = params[:user_id]
  session[:user_id] = user_id
  render plain: "Logged in as user #{user_id}"
end
```

##### 課題5: レイヤー切り替えテストの失敗

**問題:**
```ruby
# Before (エラー)
let(:lesson) { create(:lesson, items: [ "Hello" ]) }
before do
  keymap_set.keymaps.find_by(layer: 1, key_position: "L2-R0").update(character: "H")
  keymap_set.keymaps.find_by(layer: 0, key_position: "L3-R3").update(character: "Lower")
end

# 期待: Layer1キー（L3-R3）がハイライトされる
# 実際: ハイライトされない（テスト失敗）
```

**原因調査:**
```ruby
Keymap.default_keymap.select { |k| k[:character].include?("H") }
# => [{ layer: 0, key_position: "R1-R0", character: "H|h" }]
# デフォルトキーマップで"H"がLayer 0に既に存在していた
```

**JavaScriptのロジック:**
```javascript
// app/javascript/controllers/typing_controller.js
buildKeyMapping() {
  // Layer 0から順に検索し、最初に見つかった文字を使用
  for (let layer = 0; layer <= 5; layer++) {
    // ...
  }
}
```

**結果:** "H"を検索すると、Layer 1よりも先にLayer 0の`R1-R0`が見つかってしまう

**ユーザーからの指摘:**
> 「Layer 1にある場合は、LowerキーではなくLyr1キーがハイライトされるはずです👀」

コメント内の"Lowerキー"も誤りで、正しくは"Layer1"キー（またはLyr1キー）

**解決策:** デフォルトキーマップにない文字を使用
```ruby
# After (修正)
let(:lesson) { create(:lesson, items: [ "X" ]) }
before do
  # Layer 1に大文字"X"を追加（デフォルトキーマップにない文字）
  keymap_set.keymaps.find_by(layer: 1, key_position: "L2-R0").update(character: "X")
  # Layer 0のL2-R0は空文字に設定（Xを検索してもLayer 0で見つからないようにする）
  keymap_set.keymaps.find_by(layer: 0, key_position: "L2-R0").update(character: "")
  # レイヤー切り替えキー（Layer1/Lyr1）をLayer 0に追加
  keymap_set.keymaps.find_by(layer: 0, key_position: "L3-R3").update(character: "Layer1")
end

it "大文字が必要な場合はレイヤーボタンとターゲットキーの両方がハイライトされる" do
  login_as_user(user)
  visit lesson_path(lesson)

  # 1. Layer1キー（L3-R3）がハイライトされる ✅
  expect(page).to have_selector('.key.ring-2[data-position="L3-R3"]')

  # 2. "X"のキー（L2-R0）もハイライトされる ✅
  expect(page).to have_selector('.key.ring-2[data-position="L2-R0"]')
end
```

### 2. FactoryBotとActiveRecordコールバックの相性問題

`KeymapSet`の`after_create :copy_default_keymap`コールバックにより、作成時に288個のKeymapが自動生成される設計でした。

**問題:** FactoryBotで`create(:keymap, ...)`しようとすると、既にレコードが存在するため一意性制約違反

**解決パターン:**
```ruby
# ❌ 新規作成（エラー）
create(:keymap, :key_h, keymap_set: keymap_set)

# ✅ 既存レコードの更新（成功）
keymap_set.keymaps.find_by(layer: 0, key_position: "L2-R0").update(character: "h")
```

**教訓:** モデルのコールバックがテストデータ作成に影響を与える場合、「作成」ではなく「更新」のアプローチを取る

### 3. Capybaraのドライバー自動判定パターン

`rack_test`（JavaScript無効）と`selenium_chrome_headless`（JavaScript有効）で異なるAPIを持つため、ヘルパーメソッドでドライバーを自動判定する設計にしました。

```ruby
if page.driver.is_a?(Capybara::RackTest::Driver)
  # 高速だがJavaScript無効
  page.driver.post "/test/sessions", user_id: user.id
else
  # 遅いがJavaScript有効
  visit "/test/sessions?user_id=#{user.id}"
end
```

**メリット:**
- テスト側で`js: true`フラグを設定するだけで自動的に適切な方法が選ばれる
- ヘルパーメソッドのインターフェースが統一される

### 4. デフォルトキーマップとテストデータの衝突

レイヤー切り替えのテストで"H"を使おうとしたところ、デフォルトキーマップに既に"H"が存在していたため、意図しないLayer 0のキーが検出されました。

**対策:**
- デフォルトキーマップにない文字（"X"）を使用

**教訓:** テストデータは本番データの状態を考慮し、衝突しない値を選ぶ
