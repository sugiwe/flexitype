class Admin::ApplicationController < ApplicationController
  before_action :require_admin!

  private

  def require_admin!
    admin_emails = ENV['ADMIN_EMAILS']&.split(',')&.map(&:strip) || []
    unless logged_in? && admin_emails.include?(current_user.email)
      redirect_to root_path, alert: "管理者権限が必要です"
    end
  end
end

### 管理者ダッシュボード設計のベストプラクティス

#### 1. 名前空間の活用

**Admin 名前空間の設計**:
```ruby
# config/routes.rb
namespace :admin do
  root to: "dashboard#index"
  resources :users, only: [:index, :show]
end
```

**利点**:
- URL が `/admin/*` に統一され、わかりやすい
- コントローラが `app/controllers/admin/` 配下に整理される
- ビューも `app/views/admin/` 配下に整理される

#### 2. アクセス制御の実装

**環境変数による柔軟な管理**:
```bash
# .kamal/secrets
ADMIN_EMAILS=developer@example.com,admin@example.com
```

**利点**:
- データベースを使わずにシンプルに管理者を設定
- デプロイ時に環境変数を変更するだけで管理者を追加/削除可能
- セキュアに管理できる（Git にコミットしない）

#### 3. N+1 クエリの防止

**問題のあるコード**:
```ruby
@recent_sessions = TypingSession.order(completed_at: :desc).limit(10)
# ビューで @recent_sessions.each { |session| session.user.name } → N+1発生
```

**改善後**:
```ruby
@recent_sessions = TypingSession.includes(:user).order(completed_at: :desc).limit(10)
# ビューで @recent_sessions.each { |session| session.user.name } → 1回のクエリでOK
```

**効果**:
- SQLクエリの実行回数が激減（10件なら 1+10 → 1+1 回）
- ページの表示速度が向上

#### 4. レスポンシブUIの実装

**PC/モバイルの切り替え**:
```slim
/ PC: テーブル表示
.hidden.md:block.overflow-x-auto
  table.min-w-full...
    / テーブルの内容

/ モバイル: カード表示
.md:hidden.space-y-4
  / カードの内容
```

**利点**:
- モバイルではカード形式で見やすく
- PCでは情報密度の高いテーブル形式
- Tailwind CSS の `hidden`/`md:block` で簡単に切り替え

### 管理者ダッシュボードの設計思想

**ユーザー視点の統計表示**:
- 単なる数字の羅列ではなく、視覚的にわかりやすく
- アイコンと色分けで情報を整理
- サブテキストで追加情報を提供（「今週の新規登録: X名」など）

**段階的な詳細表示**:
- ダッシュボード: 全体の概要を把握
- 一覧ページ: 特定の項目（ユーザー）を一覧表示
- 詳細ページ: 個別の詳細情報を表示

### N+1 クエリ対策の重要性

**問題の発見**:
- 開発環境では気づきにくい（データ数が少ない）
- 本番環境で性能問題が顕在化する可能性

**対策の習慣化**:
- アソシエーションを使う場合は `includes` を忘れずに
- `each` ループで関連データにアクセスする場合は要注意
- Bullet gem などのツールで検出できる

### レスポンシブUIの実装パターン

**PC/モバイルの切り替え**:
- `hidden md:block` でPC版を表示
- `md:hidden` でモバイル版を表示
- 同じデータを2つの異なるレイアウトで表示

**ユーザビリティの向上**:
- モバイルではカード形式で情報を縦に並べる
- PCではテーブル形式で情報密度を高める
- デバイスに応じた最適な表示

### ドキュメント管理の重要性

**肥大化の問題**:
- CLAUDE.md が 1,663 行に達し、見通しが悪くなった
- 詳細仕様を探すのが困難になった

**リファクタリングの効果**:
- CLAUDE.md を 400 行に圧縮し、インデックス化
- 詳細仕様は専用ドキュメントに分離
- 全体像を把握しやすくなった

## まとめ

本日は、管理者ダッシュボードの実装（Phase 1-3すべて完了）と、CLAUDE.mdのリファクタリングを完了しました。

管理者ダッシュボードは、ベータテストユーザーの活動状況を監視するための強力なツールとなりました。統計サマリーカード、アクティブユーザー統計、人気レッスンランキングなど、多角的な視点でユーザーの活動を把握できます。また、個別のユーザー詳細ページでは、各ユーザーの練習履歴やキーマップを確認でき、きめ細かいサポートが可能になりました。

CLAUDE.mdのリファクタリングでは、肥大化した1つのドキュメントを、インデックスと専用ドキュメントに分離しました。これにより、プロジェクトの全体像を把握しやすくなり、詳細な仕様も探しやすくなりました。今後の機能拡張やドキュメント更新も容易になると期待しています。
